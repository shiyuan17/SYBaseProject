## Active Work

- System log management implemented on 2026-06-10: `bl-center` adds `GET /api/v1/system/logs/login`, `/login/{id}`, `/operations`, and `/operations/{id}` with permission checks, sanitized/truncated details, pagination filters, operation-log repository queries, and Flyway Java migration `V84__add_system_log_management` for menu/permission/index seed data. `ApiAuditInterceptor` records authenticated `@RequirePermission` non-GET requests and `@AuditOperation(sensitiveQuery = true)` GET requests, while `OperationAuditService` marks manually audited requests to avoid duplicate nested audit. Sibling frontend `../SYBaseProjectWeb` adds `/system/logs` with 登录日志 / 操作日志 tabs and uses the new permissions.
- Embedding confirmation rollback implemented on 2026-06-10: `POST /api/v1/embeddings/cancel` accepts the existing technical task start payload, only allows `EMBEDDING_CONFIRM_PENDING` embedding tasks, resets them to `PENDING`, clears `started_at` / `completed_at`, preserves remarks unless a cancellation remark is supplied, and writes an embedding cancel workflow event. It does not delete final embedding records or downstream slicing tasks because it is only valid before `POST /api/v1/embeddings/complete`. Sibling frontend `../SYBaseProjectWeb` adds “取消包埋” before “确认包埋完成” and calls this endpoint for selected/current confirmation-pending rows.
- Slicing pending slide-print merge groups implemented on 2026-06-09: `POST /api/v1/slicings/slide-print-merge-groups` groups selected unprinted slicing tasks by same patient, same case/pathology number, and same embedding-box letter prefix, naturally sorts each group, and creates two-item pending groups while leaving odd-tail rows unmerged. `POST /api/v1/slicings/slide-print-merge-groups/cancel` cancels pending groups, and `/print` prints pending groups then marks them printed. `GET /api/v1/slicings/workbench` excludes grouped task rows from ordinary pending print rows and returns virtual merged rows with `printGroupId`, `mergedPrintGroup`, `taskIds`, `embeddingBoxIds`, and `embeddingBoxNo` such as `A1+A2`. Sibling frontend `../SYBaseProjectWeb` adds `两两合片` / `取消合片` buttons before `打印玻片` and renders merged wax-block numbers with green highlighting.
- Specimen workflow no-barcode progression fixed on 2026-06-09: `SpecimenFixationRequest`, `SpecimenConfirmRequest`, `SpecimenCheckInRequest`, `ReceiveSpecimensRequest`, and `CreateTransportOrderRequest` now accept `specimenId` and/or `specimenNo` while keeping barcode compatibility. `SpecimenWorkflowLookupSupport` resolves `specimenId > specimenBarcode > specimenNo`, rejects ambiguous specimen-number matches with 400, and fixation/confirmation/check-in refreshes by `specimenId`. Receipt service uses the same preferred identifier resolution for normal and direct receipt. Transport creation prefers `specimenIds`; quick outbound auto-create uses resolved specimen IDs instead of constructing barcode lists. Sibling frontend `../SYBaseProjectWeb` sends row-level `specimenId` for fixation, confirmation, check-in, receipt, and outbound.
- Slicing workbench display fields changed on 2026-06-09: `GET /api/v1/slicings/workbench` row responses now include `embeddingBoxNo` from `embedding_boxes.embedding_box_no`, `embeddingRemarks` from the embedding record remark already projected as `emb.remarks`, and `submittingDepartmentName` from `applications.submitting_department_name`. Sibling frontend `../SYBaseProjectWeb` uses these fields for the `玻片打印` old-desktop column order while keeping `POST /api/v1/slicings/slide-print` unchanged.
- Slicing workbench legacy task fallback fixed on 2026-06-09: `JdbcTechnicalWorkflowProcessingQueries.findSlicingWorkbenchRows` now resolves slicing rows whose task object still points to `SAMPLING_BLOCK` by joining through `sampling_blocks` / `embedding_boxes.sampling_block_id`; `embeddingBoxNo` comes from the real embedding box or sampling block fallback, and `embeddingRemarks` falls back to `sampling_blocks.embedding_remarks` when the final embedding remark is empty. Sibling frontend `../SYBaseProjectWeb` records this as `BUG-20260609-015`.
- Slicing workbench DM GROUP BY fix on 2026-06-09: `JdbcTechnicalWorkflowProcessingQueries.findSlicingWorkbenchRows` now includes `t.object_type` in the grouped query fields, preventing DM `不是 GROUP BY 表达式` failures when sibling frontend `../SYBaseProjectWeb` opens `GET /api/v1/slicings/workbench`; recorded as backend `BUG-20260609-008`.
- Specimen outbound identifier application-scope lookup fixed on 2026-06-09: `GET /api/v1/specimen-outbounds?identifier=<barcode-or-specimenNo>` now resolves a unique exact `specimens.specimen_no` / `specimens.barcode` hit to that specimen's `applicationId`, clears the identifier filter, and returns the full application-scoped outbound list; ambiguous or missing identifier matches keep exact filtering.
