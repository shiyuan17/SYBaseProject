# CODING_RULES.md — 通用编码规范

## 目标与适用范围

本文件定义跨语言、跨模块通用的编码与审查基线。

- 适用对象：所有开发者与 AI 智能体
- 适用范围：后端代码、脚本、工具、测试、文档中的示例代码
- 规范定位：作为语言专项规范的上位规则，Java 细则以 `JAVA_RULES.md` 补充

## 强制规则

### 1. 命名与表达

- 名称必须表达业务意图，不得使用无语义缩写
- 禁止拼音命名、序号命名、含糊命名，例如 `doIt`、`temp2`、`dataList`
- 同一概念在全项目中保持统一命名

### 2. 复杂度与职责

- 函数、类、模块必须保持单一职责
- 新增逻辑优先复用现有组件，不得重复造轮子
- 复杂分支必须拆解为命名清晰的小函数或独立对象
- 大块条件分支、深层嵌套、复制粘贴代码必须重构
- 代码生成类工具与注解工具应服务于可读性和边界清晰性，不得掩盖职责混乱或对象语义缺失

### 3. 注释与文档

- 注释只解释“为什么”和“约束”，不重复“代码在做什么”
- 对外接口、公共组件、复杂规则必须具备说明文档或注释
- 代码与注释冲突时，必须同步修正文档

### 4. 异常与错误处理

- 不得吞异常、不记录上下文、不返回模糊错误
- 错误必须在合适层级处理，避免底层静默失败
- 异常信息必须便于定位问题，但不得泄露敏感信息
- CLI 应用必须区分标准输出与标准错误，不得将业务结果和错误提示混杂输出

### 5. 日志与可观测性

- 关键业务节点、失败分支、重试与外部依赖调用必须有日志或指标
- 日志必须可检索、可定位，包含业务上下文
- 日志框架必须统一，不得在同一服务中混用多套门面和实现导致配置分散
- 敏感字段必须脱敏
- 关键业务节点除了日志外，还应优先提供可聚合、可告警的指标

### 6. 空值、边界与兼容性

- 对空值、空集合、重复提交、超限输入、幂等等边界场景必须显式处理
- 修改公共能力时必须评估兼容性，不得默认破坏现有调用方
- 输出、接口、配置的默认值必须稳定且可预期
- 路径、编码、时区、换行符、文件分隔符、Shell 用法不得默认依赖单一开发机环境
- 禁止硬编码仅适用于 `x86`、GNU 用户态或大小写不敏感文件系统的行为
- 需要本地库、JNI、系统命令或容器镜像特性的实现，必须显式说明平台约束并同步遵循 `XINCHUANG_RULES.md`

### 7. 文件编码与文件健康度

- 仓库中的文本文件必须统一使用 `UTF-8` 无 `BOM`
- 默认换行符统一为 `LF`，仅 `*.cmd` 与 `*.bat` 允许使用 `CRLF`
- 源码、配置、脚本、文档、SQL、JSON、YAML、XML、Properties 等文本文件不得依赖编辑器或操作系统默认编码
- 涉及文件读写、字节转字符串、导入导出、模板加载、日志落盘、CLI 输出的实现，必须显式指定字符集
- 禁止在代码中使用 `getBytes()`、`new String(byte[])`、`FileReader`、`FileWriter` 等省略字符集的写法
- 文本文件默认健康度阈值如下：
  - `*.java` 不超过 `300` 行
  - `*.md` 不超过 `300` 行
  - `*.yml`、`*.yaml`、`*.xml`、`*.json`、`*.properties`、`*.sh`、`*.ps1`、`*.cmd`、`*.bat` 不超过 `200` 行
  - 通用文本文件体积不超过 `128 KB`
- 超过默认阈值的历史文件必须进入显式豁免清单，并记录原因；豁免仅放宽规模阈值，不放宽编码、`BOM` 与换行要求
- “文件健康度”治理聚焦文件层规则，不等同于复杂度、重复率或静态分析指标治理

### 8. 测试与审查

- 新增功能、缺陷修复、重要重构必须补充验证
- 测试至少覆盖正常路径、边界条件、失败分支
- 提交前必须完成自检，确认无明显重复、无死代码、无调试残留
- 对仓库治理规则的新增或修改，必须同步补充自动校验或明确说明无法自动化的原因

## 推荐实践

- 优先通过类型、对象模型、枚举和领域对象表达规则，而不是靠注释约束
- 用统一的错误码、日志键和追踪字段提升可观测性
- 使用统一日志技术栈与统一字段命名，避免不同模块输出格式割裂
- 对公共工具和基础能力编写使用示例，降低误用成本
- 在 Review 中优先识别行为风险、兼容性风险和维护成本，而不是只看格式
- 将平台兼容问题前置到设计阶段，而不是等到信创环境联调时再补救
- 对超长文档、导出类 JSON、大型 SQL 等历史文件，优先用豁免清单治理例外，再逐步安排专项拆分

## 反例/禁用项

- 复制现有代码后只改几个字段形成新实现
- 用注释解释一大段复杂逻辑，却不拆分结构
- 依赖调用失败后直接吃掉异常并返回成功
- 在日志、异常、接口响应里输出明文密码、Token、密钥
- 为了尽快交付留下大量 `TODO`、调试打印、魔法值却没有说明
- 新增文本文件时混用 `UTF-8 with BOM`、`GBK`、`ANSI` 或随操作系统变化的默认编码
- 为绕过文件健康度门禁，把大段结构化内容塞进字符串常量或单文件脚本中

## 检查清单

- [ ] 命名清晰且术语统一
- [ ] 职责边界清晰，无明显重复逻辑
- [ ] 复杂规则有注释或文档说明
- [ ] 异常、日志、边界处理完整
- [ ] 兼容性影响已评估
- [ ] 文本文件使用 `UTF-8` 无 `BOM`
- [ ] 换行符符合 `LF` 默认规则，`cmd/bat` 例外已合理控制
- [ ] 已评估文件规模是否超出默认健康度阈值，必要时补充豁免说明
- [ ] 测试和自检已完成
