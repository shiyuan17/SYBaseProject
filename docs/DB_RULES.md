# DB_RULES.md — 数据库设计与数据访问规范

## 目标与适用范围

本文件定义数据库设计、SQL 编写、迁移执行、回滚准备与 DDD 数据访问边界。

- 适用对象：后端开发者、DBA、运维、AI 助手
- 适用范围：表设计、索引设计、SQL、Flyway 脚本、仓储实现、达梦与信创数据库兼容处理
- 规范定位：统一数据模型与迁移治理方式，避免数据库成为隐形耦合点

## 强制规则

### 1. 建模与命名

- 表名、字段名、索引名使用统一英文命名规范，避免缩写泛滥
- 主键策略、审计字段、状态字段、逻辑删除字段必须统一
- 金额、数量、比率、时间字段必须使用能表达业务精度的类型
- 不得使用模糊字段名，如 `flag`、`value1`、`remark2`

### 2. DDD 数据访问边界

- 仓储接口定义在 `domain`
- 仓储实现、Mapper、DO、SQL、数据源配置定义在 `infrastructure`
- 领域层不得感知表结构、SQL 方言和 ORM 细节
- 应用层不得直接依赖具体 Mapper 绕过仓储抽象

### 3. SQL 与性能基线

- 查询必须命中合适索引，避免全表扫描成为默认路径
- 批量写入、批量更新、分页查询必须有规模上限
- 禁止 `SELECT *`
- 禁止在循环中逐条发起数据库查询或更新
- 复杂查询必须评估执行计划与锁影响

### 4. 事务、锁与一致性

- 事务边界由应用层控制，数据库操作实现必须服从事务语义
- 高并发更新场景必须明确采用乐观锁、悲观锁或幂等控制
- 长事务、跨服务分布式事务必须谨慎使用并说明理由
- 逻辑删除必须与唯一索引、查询条件、审计策略一起设计

### 5. 迁移与回滚

- 所有结构变更必须通过 Flyway 或团队指定迁移工具执行
- 迁移脚本必须可审计、可重复执行、可在 `staging` 验证
- 破坏性变更必须提前准备回滚或补偿方案
- 未经审核不得修改已在生产执行过的历史迁移脚本

### 6. 信创数据库兼容要求

- 达梦兼容是数据库设计与发布的硬门槛，不得仅在通用数据库上验证后直接上线
- SQL 语法、关键字、大小写、字段类型、日期函数、分页语法、索引行为必须评估达梦兼容性
- 使用第三方框架自动生成 SQL 时，必须验证在达梦上的实际执行结果
- 涉及 BLOB、CLOB、时间精度、字符集、排序规则、默认值表达式时必须做兼容验证
- 迁移脚本、驱动版本、连接参数与批处理行为必须保留达梦验证记录和兼容差异说明

## 推荐实践

- 为核心表统一设计 `id`、`created_at`、`updated_at`、`created_by`、`updated_by`、`deleted` 或等价字段
- 在设计阶段同步考虑唯一约束、幂等约束与查询路径
- 对复杂 SQL 保留说明：用途、数据量预期、索引依赖、风险点
- 用读模型、汇总表或异步同步降低高频复杂联表查询压力
- 在上线前通过 `EXPLAIN`、压力测试和回放数据验证关键 SQL
- 为数据库方言差异维护最小兼容说明，避免在业务代码中散落特判

## 反例/禁用项

- 在领域层拼接 SQL 或直接操作 Mapper
- 先上线代码、后补迁移脚本
- 修改生产历史迁移脚本来“修正”问题
- 没有索引评估就新增复杂查询接口
- 依赖数据库默认排序、默认时区、默认字符集获得“正确结果”

## 检查清单

- [ ] 表、字段、索引命名统一且语义清晰
- [ ] 仓储接口与持久化实现分层正确
- [ ] 关键 SQL 已评估索引、执行计划与并发影响
- [ ] 事务、锁、逻辑删除和唯一约束设计完整
- [ ] 迁移脚本已审核、验证并准备回滚方案
- [ ] 达梦兼容性已验证
- [ ] 达梦验证记录和兼容性差异说明已留档
