## 第二批业务闭环

### 报告修订审批

- 新增 `report_revision_requests`。
- 只允许对 `SIGNED` 或 `PUBLISHED` 报告发起修订申请。
- 修订审批通过后：
  - 当前 `pathology_reports.version_no + 1`
  - 当前报告状态重置为 `DRAFT`
  - 清空审核、签发、发布时间及对应人员字段
  - 保留原 `report_no`
  - 诊断任务回退到 `IN_PROGRESS`
  - 病例状态回退到 `DIAGNOSING`
- 已发布旧版本继续通过 `report_versions` 追溯，不直接改历史快照。
- 已落接口：
  - `POST /api/v1/report-revision-requests`
  - `POST /api/v1/report-revision-requests/{id}/approve`
  - `POST /api/v1/report-revision-requests/{id}/reject`

### 医嘱闭环

- 新增 `medical_orders`。
- 本批只做技术执行域 `TECHNICAL`，不接真实计费，不接外送。
- 支持的 `order_type`：
  - `RECUT`
  - `DEEP_CUT`
  - `RE_STAIN`
  - `SPECIAL_STAIN`
  - `IHC_PLACEHOLDER`
- 状态流转：
  - `PENDING -> IN_PROGRESS -> COMPLETED/CANCELLED`
- 开单医生可创建、取消。
- 技术执行角色可查询、接单、完成。
- 已落接口：
  - `POST /api/v1/medical-orders`
  - `GET /api/v1/medical-orders/pending`
  - `POST /api/v1/medical-orders/{id}/accept`
  - `POST /api/v1/medical-orders/{id}/complete`
  - `POST /api/v1/medical-orders/{id}/cancel`

### 科内会诊

- 新增 `consultation_cases` 与 `consultation_participants`。
- 本批只做 `INTERNAL` 会诊。
- 主持人默认由发起人承担，并自动作为参与人入单。
- 参与人角色首批支持：
  - `HOST`
  - `EXPERT`
  - `RECORDER`
- 状态流转：
  - `PENDING -> IN_PROGRESS -> COMPLETED`
- 仅被邀请参与人可评论。
- 仅主持人可完成会诊。
- 完成后只回流轨迹和工作台标记，不自动改报告状态。
- 已落接口：
  - `POST /api/v1/consultations`
  - `POST /api/v1/consultations/{id}/participants/{participantId}/comment`
  - `POST /api/v1/consultations/{id}/complete`
