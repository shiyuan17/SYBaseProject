# M2 临床送检与标本接收闭环规划

## 目标

- 在 `bl-center` 内完成“临床申请 -> 标本采集 -> 固定核对 -> 转运 -> 病理接收”闭环主链路。
- 让申请单、标本、转运单、接收记录和轨迹事件可全程追踪。
- 在病理接收环节生成正式病理号和病例记录，并向技术流程投递待办占位。

## 本期范围

- 扩展 `Application` 快照字段，补齐患者、送检科室、送检医生、来源医院和外部申请号信息。
- 新增 `PathologyCase`、`Specimen`、`SpecimenCollectionRecord`、`SpecimenFixationRecord`、`TransportOrder`、`TransportOrderItem`、`SpecimenReceipt`、`WorkflowEvent`、`TechnicalPendingTask`。
- 新增接口组：
  - `POST /api/v1/clinical-applications/import`
  - `POST /api/v1/specimens/register`
  - `POST /api/v1/specimen-fixations/start`
  - `POST /api/v1/specimen-fixations/complete`
  - `POST /api/v1/transport-orders`
  - `POST /api/v1/transport-orders/{id}/print`
  - `POST /api/v1/transport-orders/{id}/handover`
  - `POST /api/v1/specimen-receipts`
  - `GET /api/v1/applications/{id}/tracking`
  - `GET /api/v1/specimens/barcodes/{barcode}/tracking`
- 保留现有 `POST /api/v1/applications` 与 `GET /api/v1/applications/{id}`，其中详情接口升级为聚合视图。

## 实现说明

### 申请与外部占位

- `Application` 继续作为聚合入口，M2 不额外拆新业务中心。
- 新增 `ClinicalApplicationGateway` 占位接口，默认 `StubClinicalApplicationGateway` 仅支持 `MOCK-` 前缀的外部申请号，用于本地和测试验证。
- 导入接口通过占位网关拉取患者和申请信息，再统一落为内部 `CreateApplicationCommand`。

### 标本登记与标签打印

- 标本登记支持一申请多标本。
- 标本号沿用 `NumberingService.generateSpecimenNo`，条码支持人工传入；未传入时按 `applicationNo-specimenNo` 自动生成。
- 新增 `LabelPrintGateway` 占位接口，默认实现为可控桩：
  - 正常打印返回成功。
  - `printerCode=FAIL` 时返回失败。
- 打印失败不会回滚标本登记，但会写入轨迹事件和标本备注。

### 固定、转运与接收

- 固定环节采用 `start` / `complete` 两步接口，更新固定记录与标本状态。
- 转运单创建前强校验标本已完成固定。
- 转运支持建单、打印、交接三步，交接后申请状态进入 `IN_TRANSIT`。
- 接收支持 `RECEIVED`、`REJECTED`、`RETURNED`：
  - 首个成功接收的标本会创建 `PathologyCase` 并生成正式病理号。
  - 全部接收完成时申请状态更新为 `RECEIVED`。
  - 部分接收时更新为 `PARTIALLY_RECEIVED`。
  - 全部未接收且已处理时更新为 `REJECTED`。

### 轨迹与待办

- 所有关键状态变化都落 `workflow_events`，记录节点、动作、结果、时间、操作人和终端。
- 查询轨迹时聚合返回：
  - 申请基础信息
  - 当前节点
  - 异常标记
  - 标本摘要
  - 时间线事件
- 接收成功后写入 `technical_pending_tasks`，作为 M3 技术流程的待办占位。

## 测试与验收

- 已补充 M2 集成测试覆盖：
  - 正常主链路：申请创建、2 个标本登记、固定、转运、接收、轨迹查询。
  - 异常链路：未固定禁止转运。
  - 部分接收链路：1 个接收、1 个拒收，申请状态更新为 `PARTIALLY_RECEIVED` 且轨迹标记异常。

## 当前默认与后续建议

- M2 只覆盖常规病理送检到接收，不包含冰冻追加常规、收费落账、外院会诊、拍照归档。
- 当前以占位网关完成外部系统和打印链路的防腐层，不绑定具体 HIS 厂商或打印设备协议。
- `SpecimenWorkflowAppService` 和 `JdbcSpecimenWorkflowRepository` 当前承担了较多编排与持久化职责，后续可按工作站和读写职责继续拆分。
