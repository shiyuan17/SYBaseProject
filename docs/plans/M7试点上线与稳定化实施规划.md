# M7 试点上线与稳定化实施规划

## 摘要

- `M7` 目标不是继续扩功能，而是让“常规病理主闭环 + `M6` 三条主链路 + 基础观测/发布/培训”在单试点科室连续运行。
- 本期实现坚持加性稳定化：不新开 `M7` 控制器族，不重命名既有 `M2-M6` 接口，不改既有状态枚举语义。
- 试点默认周期 `2` 周，节奏固定为：
  1. 上线前彩排
  2. 上线日灰度和值守
  3. 首周日清
  4. 第二周周清与退出评估

## 1. 范围与边界

- 试点纳入范围：
  - 常规病理送检、接收、技术、诊断、报告主闭环
  - `M6` 临床导入
  - `M6` 收费回写与对账
  - `M6` 历史报告查询
  - `M6` 质控/运营统计查询与导出
- 明确不纳入首轮试点：
  - 冰冻、细胞学、液基、免疫组化、分子病理扩展能力
  - 采购流程
  - 真实文件上传
  - 未经过 `staging` 验证的新需求

## 2. M6 准入门禁

- 以 [M6准入收口说明.md](./M6准入收口说明.md) 为前置门禁，所有 `M6` 回归必须通过。
- 试点前只允许合入：
  - 主链路阻断缺陷修复
  - 可观测性补齐
  - 发布与回滚门禁缺口修复
- 数据库策略：
  - 沿用 `V26/V27` 作为现有基线
  - 新增变更必须提供回滚或人工补偿方案
  - 不做破坏性结构变更

## 3. 稳定化实现项

### 3.1 运维查询与追踪

- 扩展 `M6` 接口可见性，至少暴露：
  - 集成任务请求/响应载荷
  - 失败码、失败原因
  - 重试次数、下次重试时间、补偿状态、对账状态、解决时间
  - 收费记录关联集成任务摘要
  - 历史导入任务关联集成任务摘要
- 扩展查询过滤项，至少支持：
  - 集成任务按 `businessId`、`stageCode`、`externalSystem`、补偿状态、对账状态过滤
  - 收费记录按 `caseId`、`orderId`、外部系统过滤
  - 历史导入任务按 `patientId`、`pathologyNo`、`applicationNo` 过滤
  - 历史报告按 `externalReportNo` 过滤

### 3.2 可观测性

- `bl-center` 新增并统一输出以下业务指标：
  - 临床导入成功量、失败量、耗时
  - 收费提交、回执、重试、对账成功量、失败量、耗时
  - 历史报告导入成功量、失败量、耗时
  - 统计查询、导出成功量、失败量、耗时
- 新增积压/异常 Gauge：
  - `integration_retry_pending_count`
  - `integration_manual_required_count`
  - `billing_reconciliation_discrepancy_count`
  - `historical_import_running_count`
- 监控资产补齐到 `infrastructure/monitor/`：
  - `bl-center` 看板
  - `bl-center` 告警规则
  - 试点环境可复用的 Prometheus/Grafana 说明

### 3.3 异常兜底

- 临床导入失败：允许人工创建申请单并保留外部单号，恢复后补录集成任务追踪。
- 收费失败：允许管理员按收费记录重试、回执确认、对账确认，保留失败原因与补偿状态。
- 历史导入失败：允许按来源系统、申请单号、病理号定点重试，并保留去重逻辑。
- 统计异常：查询失败不得影响主业务，允许缩小时间窗重查或改为导出补查。

## 4. 上线准备

### 4.1 发布流程

- 发布、灰度、回滚遵循 [RELEASE.md](../rules/RELEASE.md)。
- 固定发布路径：
  1. `staging` 全链路验证
  2. 试点灰度发布
  3. 小范围值守
  4. 扩到试点全员
- 发布前必须明确：
  - 版本号
  - 发布窗口
  - 值班表
  - 通知对象
  - 回滚责任人

### 4.2 岗位材料

- 试点前补齐四类 `SOP`：
  - 护士
  - 技师
  - 医生
  - 管理员
- 异常手册至少覆盖：
  - 导入失败
  - 收费失败
  - 历史导入重复/失败
  - 统计导出异常
  - 权限缺失
  - 发布回滚

## 5. 试点执行与退出标准

- 每日输出问题清单，按 `阻断 / 高频 / 一般` 三级分流。
- 每条问题必须记录：
  - 根因分类
  - 修复版本
  - 临时绕行方案
  - 验证结果
- 试点退出标准：
  - 常规病理主闭环可连续运行
  - `M6` 三条主链路稳定可用
  - 四类岗位 `SOP` 可执行
  - 监控告警可触达值班人
  - 关键异常有人工兜底
  - 未关闭阻断项为 `0`

## 6. 测试与演练

- 自动化回归：
  - `M1-M5` 既有回归
  - `M6ClinicalIntegrationTest`
  - `M6BillingIntegrationTest`
  - `M6HistoricalReportIntegrationTest`
  - `M6StatisticsIntegrationTest`
  - `M6AuthorizationIntegrationTest`
  - `M6ObservabilityIntegrationTest`
- 发布演练至少覆盖：
  - `/actuator/health`
  - `/actuator/prometheus`
  - Prometheus 抓取
  - Grafana 看板
  - 告警触达
  - Docker 部署
  - 回滚上一稳定版本

## 假设与默认决策

- 默认以单试点科室为首轮目标，不追求多科室并行上线。
- 默认 `bl-center` 为试点主业务中心，`auth-center` 与 `user-center` 继续沿用既有能力。
- 默认试点阶段功能冻结，除阻断缺陷、高频体验问题和门禁缺口外不接新增需求。
