# M6 准入收口说明

## 摘要

- 本文档用于确认 `bl-center` 已具备进入 `M7` 试点上线准备阶段的 `M6` 基线能力，并明确试点前必须冻结与补齐的范围。
- `M6` 当前以仓库内已落地代码、Flyway 迁移、接口测试和权限测试为准，不再额外扩展新的业务域。
- `M7` 前置修复只接受两类事项：
  - 影响试点主链路可用性的缺陷
  - 影响故障定位、恢复和回滚的可观测性缺口

## 已落实范围

### 1. 集成与导入

- 已落接口：`POST /api/v1/clinical-applications/import`
- 已保留外部标识：`thirdPartySource`、`externalOrderNo`
- 已写入集成任务轨迹：`integration_tasks`
- 当前验证用例：`M6ClinicalIntegrationTest`

### 2. 收费回写与对账

- 已落接口：
  - `GET /api/v1/billing-records`
  - `POST /api/v1/billing-records/{id}/receipt`
  - `POST /api/v1/billing-records/{id}/retry`
  - `POST /api/v1/billing-records/reconcile`
- 已覆盖场景：
  - 特检医嘱收费提交失败后重试成功
  - 报告发布收费成功后接收回执
  - 集成任务状态、重试次数、补偿状态、对账状态可追溯
- 当前验证用例：`M6BillingIntegrationTest`

### 3. 历史报告导入与查询

- 已落接口：
  - `POST /api/v1/historical-report-import-jobs`
  - `GET /api/v1/historical-report-import-jobs`
  - `GET /api/v1/historical-reports`
- 已覆盖场景：
  - 历史报告导入
  - 二次导入去重与版本重建
  - 导入任务可按来源、病理号、申请单号追踪
- 当前验证用例：`M6HistoricalReportIntegrationTest`

### 4. 统计分析

- 已落接口：
  - `GET /api/v1/stat-indicators`
  - `GET /api/v1/stat-report-templates`
  - `POST /api/v1/stat-reports/query`
  - `POST /api/v1/stat-reports/export`
- 已落库资产：
  - `V26__create_m6_integration_billing_history_stats_schema.sql`
  - `V27__seed_m6_authorization_and_indicator_defs.sql`
- 已覆盖能力：
  - 十三项病理质控指标定义
  - 科室运营与工作量统计
  - CSV 导出
- 当前验证用例：`M6StatisticsIntegrationTest`

### 5. 权限矩阵

- 已落菜单、权限、角色授权：`M6PermissionCodes` + `V27`
- 当前验证用例：`M6AuthorizationIntegrationTest`
- 默认授权边界：
  - `ROLE_PATHOLOGY_ADMIN`：集成任务、收费、历史、统计全量能力
  - `ROLE_ARCHIVE_MANAGER`：历史导入与历史查询
  - `ROLE_QUALITY_MANAGER`：统计查询与导出

## M7 前置门禁

- `M6` 试点准入以以下自动化回归全部通过为前提：
  - `M6ClinicalIntegrationTest`
  - `M6BillingIntegrationTest`
  - `M6HistoricalReportIntegrationTest`
  - `M6StatisticsIntegrationTest`
  - `M6AuthorizationIntegrationTest`
  - `M6ObservabilityIntegrationTest`
- `M1-M5` 基线回归不得回退。
- `V26/V27` 作为当前 `M6` 数据基线；试点前若暴露数据库问题，只允许追加：
  - 非破坏性兼容修复
  - 性能索引
  - 审计与状态补齐
  - 配套回滚脚本或人工补偿说明

## 冻结与阻断项规则

- 进入 `M7` 后冻结新的 `M6+` 需求，不新增独立 `M7` 业务域。
- 以下问题视为阻断项，必须在试点前关闭：
  - 临床导入重复、丢单或不可恢复失败
  - 收费失败后无可执行重试/补账路径
  - 历史报告重复导入导致脏数据或不可追溯
  - 统计查询/导出无法稳定完成
  - 关键集成任务无失败原因、重试状态、补偿状态或监控告警

## 当前结论

- 结论：`M6` 已具备进入 `M7` 试点准备的代码与测试基线，但必须在试点前完成可观测性收口、发布演练、岗位 `SOP` 和试点验收材料。
- 后续实施以 [M7试点上线与稳定化实施规划.md](./M7试点上线与稳定化实施规划.md) 与 [M7试点验收清单.md](./M7试点验收清单.md) 为准。
