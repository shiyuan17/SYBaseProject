# M4 医生诊断与报告闭环规划

## 目标

在 `bl-center` 内完成医生诊断主链路的最小闭环，让 M3 染色出片后的病例能够继续进入：

1. 诊断任务查询与分派
2. 诊断接收与开始
3. 报告草稿创建、保存、提交
4. 审核、驳回、签发、发布
5. 工作台查询与报告跟踪查询

本轮只做整改，不新增新的 M4 业务功能。

## 本期已实现范围

当前代码和测试口径只覆盖以下能力：

- `GET /api/v1/diagnostic-tasks/pending`
- `POST /api/v1/diagnostic-tasks/{id}/assign`
- `POST /api/v1/diagnostic-tasks/{id}/accept`
- `POST /api/v1/diagnostic-tasks/{id}/start`
- `GET /api/v1/pathology-cases/{id}/diagnostic-workbench`
- `POST /api/v1/pathology-reports`
- `POST /api/v1/pathology-reports/{id}/save-draft`
- `POST /api/v1/pathology-reports/{id}/submit`
- `POST /api/v1/pathology-reports/{id}/review`
- `POST /api/v1/pathology-reports/{id}/reject`
- `POST /api/v1/pathology-reports/{id}/sign`
- `POST /api/v1/pathology-reports/{id}/publish`
- `GET /api/v1/pathology-cases/{id}/report-tracking`

本期保留的核心实体与读模型包括：

- `diagnostic_tasks`
- `pathology_reports`
- `report_versions`
- `workflow_events`
- 医生工作台聚合查询
- 报告跟踪聚合查询

## 明确不在本期交付的能力

以下内容不在本轮验收范围，统一转入 backlog：

- `POST /api/v1/pathology-reports/{id}/delay-publish`
- 修订申请与修订审批
- 科内会诊
- 医嘱开立、取消、待执行列表
- 玻片质控录入
- 外部会诊、收费对接、正式 PDF 渲染打印

本轮不补这些接口，不新增相关表逻辑，也不把它们写入验收承诺。

## 业务边界

- `bl-center` 继续作为唯一真实业务中心，不新增独立报告中心或任务中心。
- 所有关键动作继续写入 `workflow_events`，用于审计与跟踪。
- 报告主链路以当前已实现的角色模型和任务模型为准。
- 发布前链路必须经过任务接收、开始、提交、审核、签发等显式动作。

## 当前实现约束

- 审核、驳回必须由任务指定审核人执行。
- 发布必须由实际签发人执行。
- 创建、保存草稿、提交必须由任务指定诊断医生执行。
- 工作台和跟踪查询保持既有响应结构，不在本轮调整返回模型。

## 验收口径

本期验收只按以下场景执行：

1. M3 染色完成后生成诊断任务
2. 分派后由责任医生接收并开始
3. 创建报告草稿并保存
4. 提交审核后由审核人审核或驳回
5. 审核通过后由签发人签发并发布
6. 在工作台和报告跟踪中看到一致的状态与轨迹
7. 越权用户无法推进不属于自己的节点
