# M5补齐归档与运营支撑实施规划

## 摘要

- 本期 M5 范围固定为“归档/借阅 + 试剂/设备台账支撑”，不纳入运营统计报表、Excel 导出、采购流程和收费联动，这些继续放在 M6。
- 归档能力第一版直接采用“归档柜-柜位-存储记录-借阅记录”的精细模型，不走纯文本位置过渡方案。
- 由于当前工作区已有未提交的 `V20`、`V21` 迁移，本次 M5 实际顺延使用 `V22`、`V23`、`V24`，避免覆盖现有改动。
- 实施按 3 批推进：
  1. 数据库与 RBAC 种子
  2. 归档/借阅闭环与医生查询回流
  3. 试剂/设备台账、预警与运维收口

## 关键改动

### 1. 数据库与种子

- 新增 Flyway：
  - `V22__create_m5_archive_operation_schema.sql`
  - `V23__seed_m5_archive_operation_authorization.sql`
  - `V24__reconcile_m5_archive_operation_authorization.java`
- 新增表：
  - `archive_cabinets`
  - `archive_positions`
  - `specimen_storage_records`
  - `material_loans`
  - `reagents`
  - `reagent_stocks`
  - `equipment_records`
  - `equipment_maintenance_logs`
- 不新增 `archives` 报告归档表：
  - 电子/拍照件复用 `case_media_assets`
  - 纸质件柜位落到 `specimen_storage_records`
- 复用现有 `workflow_events`
  - `node_code = ARCHIVE`
  - `action_code` 只新增 `ARCHIVE`、`BORROW`、`RETURN`
- 复用现有角色：
  - `ROLE_PATHOLOGY_ADMIN`
  - `ROLE_ARCHIVE_MANAGER`
  - `ROLE_REAGENT_DEVICE_MANAGER`
- 新增 `M5PermissionCodes`

### 2. 归档与借阅闭环

- 在 `bl-center` 新增归档领域服务与仓储：
  - `ArchiveWorkflowService`
  - `ArchiveQueryService`
  - `ArchiveRepository`
- 归档对象定义：
  - 申请单：`APPLICATION_FORM`
  - 蜡块：`EMBEDDING_BOX`
  - 玻片：`SLIDE`
- 归档柜管理规则：
  - 创建时直接传 `cabinetType + layerCount + slotCountPerLayer`
  - 系统自动生成 `archive_positions`
  - `position_code` 规则固定为 `${cabinetCode}-L${layerNo}-S${slotNo}`
  - 一个柜位同一时刻只能占用一个对象
- 归档接口：
  - `GET /api/v1/archive-cabinets`
  - `POST /api/v1/archive-cabinets`
  - `PATCH /api/v1/archive-cabinets/{id}`
  - `GET /api/v1/archive-positions/available`
  - `POST /api/v1/archive/application-forms`
  - `POST /api/v1/archive/embedding-boxes`
  - `POST /api/v1/archive/slides`
  - `GET /api/v1/archive-records/search`
  - `GET /api/v1/material-loans/pending`
  - `POST /api/v1/material-loans`
  - `POST /api/v1/material-loans/{id}/return`
- 拍照归档复用现有 URL 模式，不做文件上传服务：
  - 申请单照片：`case_media_assets.object_type = APPLICATION_FORM`
  - 归档照片：`case_media_assets.media_type = ARCHIVE_IMAGE`
- 查询回流到医生场景：
  - `DiagnosticWorkbenchResponse.BlockSummary` 追加 `archiveStatus`、`archiveLocation`、`loanStatus`
  - `DiagnosticWorkbenchResponse.SlideSummary` 追加同名字段
  - 工作台/追踪根节点追加 `applicationFormArchiveStatus`、`applicationFormArchiveLocation`、`applicationFormImageUrl`

### 3. 试剂与设备台账支撑

- 新增 `OperationSupportService` 与 `OperationSupportRepository`
- 试剂接口：
  - `GET /api/v1/reagents`
  - `POST /api/v1/reagents`
  - `PATCH /api/v1/reagents/{id}`
  - `GET /api/v1/reagent-stocks`
  - `POST /api/v1/reagent-stocks`
  - `PATCH /api/v1/reagent-stocks/{id}`
  - `GET /api/v1/reagent-stocks/warnings`
- 设备接口：
  - `GET /api/v1/equipment-records`
  - `POST /api/v1/equipment-records`
  - `PATCH /api/v1/equipment-records/{id}`
  - `GET /api/v1/equipment-records/{id}/maintenance-logs`
  - `POST /api/v1/equipment-records/{id}/maintenance-logs`
  - `GET /api/v1/equipment-records/warnings`
- 试剂/设备的新增与维护统一接入现有 `OperationAuditService`，不写 `workflow_events`

## 假设与默认决策

- M5 不做运营统计报表、Excel 导出、采购流程、收费联动、真实文件上传。
- 申请单照片继续使用 URL 方式入库，不新增对象存储适配层。
- 蜡块实体以 `embedding_boxes` 作为归档与借阅对象，不再新造独立 block 实物表。
- 申请单、蜡块、玻片全部纳入统一病例主线，所有归档/借阅记录都必须带 `case_id`。
- 本期不新增前端页面代码；通过菜单、权限、OpenAPI 和集成测试把后端契约补齐，供后续前端或外部工作台接入。
