# XINCHUANG_RULES.md — 信创兼容与国产化门禁规范

## 目标与适用范围

本文件定义项目在信创环境下的适配目标、技术选型约束、兼容验证要求、发布门禁与例外审批机制。

- 适用对象：研发、测试、架构、运维、AI 助手
- 适用范围：操作系统、CPU 架构、JDK、数据库、中间件、浏览器/客户端、驱动、镜像、第三方依赖、脚本工具
- 规范定位：作为国产化兼容专项规范，为开发、联调、发布提供硬性门禁

## 强制规则

### 1. 信创基线

- 默认以“可运行于国产 OS + 国产 CPU + 国产数据库/中间件组合”为目标
- 未通过信创兼容验证的实现，不得宣称具备可发布状态
- 本地开发环境验证结果不能替代信创环境验证结果

### 2. 选型与依赖约束

- 新增技术组件必须优先选择可提供国产化兼容证明、适配说明或替代方案的产品
- 新增第三方库、驱动、镜像、Agent、脚本工具必须评估国产环境可用性
- 无兼容证明、无替代方案或无验证计划的依赖，不得直接进入默认技术栈
- 涉及本地库、JNI、系统命令、浏览器内核、字体渲染、压缩工具时，必须额外说明平台约束
- 使用 `Lombok` 等注解处理工具时，必须确认 IDE、CI、构建链路和国产 JDK 环境可稳定处理注解生成代码

### 3. 开发与实现约束

- 禁止硬编码平台相关路径、Shell 语法、x86-only 二进制依赖、未验证的 JNI 或本地库依赖
- 禁止默认依赖 GNU 专有命令、大小写不敏感文件系统行为、单一时区或单一字符集假设
- 安装脚本、Dockerfile、启动参数、JVM 参数必须保留国产环境适配说明

### 4. 数据库与中间件约束

- 数据库兼容以达梦验证为最低门槛
- 缓存、MQ、对象存储、任务调度、搜索、监控等组件必须说明国产环境部署方式、驱动版本与适配边界
- 使用自动生成代码、自动生成 SQL 或自动装配脚本的场景，必须验证在信创环境中的实际结果
- `Prometheus exporter`、`Actuator`、`Micrometer`、`Grafana` 面板与采集链路必须验证在国产环境可运行

### 5. 测试与验证要求

- 必须区分“本地功能通过”和“信创环境通过”
- 信创验证至少覆盖：应用启动、数据库访问、字符编码、时区处理、文件路径、任务调度、外部依赖连接、镜像运行
- 监控采集链路、时区、字符集、容器镜像与面板展示能力必须在信创环境验证
- 验证结果必须可追溯，至少记录环境组合、版本、问题结论和处理状态

### 6. 发布门禁与例外审批

- 未通过信创兼容验证的版本，不得进入 `staging` 或 `prod`
- 发布前必须更新兼容矩阵、验证记录、例外审批状态与替代方案进度
- 不兼容项必须登记影响范围、临时绕过方式、替代方案、责任人和整改截止时间
- 任何例外放行都必须经过人工审批并留档

## 推荐实践

- 维护兼容矩阵，覆盖 OS / CPU / JDK / DB / 中间件 / 浏览器或客户端组合
- 为常见依赖维护“已验证 / 待验证 / 禁用”清单
- 对脚本工具、部署镜像、JVM 参数、文件处理链路做专项回归
- 为信创问题建立单独问题台账，避免兼容性缺陷在发布周期末集中爆发

## 反例/禁用项

- 只在 x86 macOS 或通用 Linux 验证就宣称“可上线”
- 引入驱动、中间件或镜像时没有国产替代评估
- 通过手工修改线上环境规避兼容问题，却不补文档和验证记录
- 把信创验证当成发布前可选项，而不是硬性门禁

## 检查清单

- [ ] 已明确本次改动涉及的 OS / CPU / JDK / DB / 中间件组合
- [ ] 新增依赖、驱动、镜像、脚本工具已完成信创可用性评估
- [ ] 达梦及相关中间件兼容验证已完成
- [ ] 已记录兼容矩阵、验证结果、差异说明和处理状态
- [ ] 不兼容项已完成例外审批并明确整改计划
- [ ] 未通过信创验证的版本未进入候选发布流程
